# 마케팅 트렌드 리포트 자동화

마케팅 직무 준비생과 현직자가 최신 트렌드를 빠르게 훑고 팔로업할 수 있도록, Claude가 웹을 조사해 리포트를 자동으로 만든다.

| 종류 | 실행 시각 | 다루는 기간 | 내용 |
|---|---|---|---|
| 데일리 | 매일 09:00 | 최근 48시간 | 눈에 띄는 마케팅 아이디어, 최신 밈, 브랜드·업계 뉴스 (화·금엔 인스타 캐러셀·릴스 섹션 추가, 주말엔 밈 위주 주말판) |
| 위클리 | 매주 월 09:10 | 지난주 월~일 | 그 주 가장 이슈였던 트렌드 TOP, 밈, 주목할 캠페인 |
| 먼슬리 | 매월 1일 09:20 | 지난달 | 그 달 TOP 트렌드, 밈·키워드, 베스트 캠페인, 업계 변화 |
| 분기 | 1·4·7·10월 1일 09:30 | 지난 분기 | 브랜드·대기업·대행사·리서치 기관의 트렌드 리포트 정리 |

리포트는 **`office.html`**(마케팅팀 오피스)을 브라우저로 열어서 본다. 새 리포트가 나오면 macOS 알림이 뜬다. 목록형으로 보고 싶으면 `list.html`.

## 🏢 마케팅팀 오피스 (`office.html`)
픽셀아트 사무실에 팀원 4명이 스케줄대로 출근해서 리포트를 보고한다.

| 팀원 | 담당 | 출근 |
|---|---|---|
| 하루 사원 | 데일리 | 09:00 |
| 주디 대리 | 위클리 | 09:10 |
| 달래 과장 | 먼슬리 | 09:20 |
| 쿼터 차장 | 분기 리포트 리서치 | 09:30 |

- **로그인:** 처음 열면 닉네임·전화번호·이메일(선택)을 입력해서 들어온다. 새로 가입한 사람은 가입한 뒤에 발행된 리포트만 받는다. 같은 전화번호로 다시 들어오면 그 계정의 기록을 이어서 보고, 로그인 기능 전부터 쓰던 기록은 그 브라우저에서 처음 로그인한 계정이 지난 리포트까지 그대로 이어받는다. 로그아웃은 ⚙️ 설정에서. 계정 정보는 서버 없이 브라우저에만 저장된다.
- **출근·보고:** 출근 시각에 문으로 들어와 자리에 앉는다. 담당 리포트가 아직 안 나왔으면 "작성 중", 안 읽은 리포트가 있으면 내 책상으로 와서 보고를 기다린다. 18시에 퇴근하지만 보고할 게 남아 있으면 야근한다.
- **읽기:** 팀원(또는 오른쪽 팀원 카드)을 누르면 보고서가 열린다. 끝까지 보고 "다 읽었어요"를 누르면 경험치를 얻는다 (데일리 10 · 위클리 25 · 먼슬리 40 · 분기 60, 3일 이상 연속이면 +5).
- **확인 퀴즈:** 읽음 완료 후 담당 팀원이 퀴즈 3문제(주말판 2문제)를 낸다. 처음 풀 때만 정답마다 +5 XP, 만점이면 +5 보너스. 다시 풀기는 보고서 아래 버튼으로.
- **인스타 트렌드 (화·금):** 화·금요일 데일리에는 '인스타 캐러셀·릴스 트렌드' 섹션이 붙는다. 릴스 포맷·트렌딩 오디오, 캐러셀 구성, 브랜드 계정 사례, 기능·알고리즘 업데이트를 다루고, 카드마다 📱 구성 뜯어보기(릴스는 초 단위, 캐러셀은 장 단위)와 원본 게시물·해시태그 바로가기가 있다. 인스타그램은 로그인 없이 열리지 않아서 트렌드 블로그·기사·검색 결과로 조사하므로, 원본 링크가 없는 카드도 있다. 내용은 `prompts/insta_section.md`에서 바꾼다.
- **주말:** 토·일요일엔 하루 사원만 캐주얼 차림으로 출근해서 밈 위주의 짧은 "주말판"을 보고한다. 나머지 팀원은 주말 휴무 (1일이 주말이면 먼슬리·분기 담당은 출근).
- **승진:** 경험치가 쌓이면 인턴 → 사원 → … → CMO로 승진하고, 사무실에 화분·커피머신·화이트보드·책장·소파·네온사인·트로피·휴게 공간·야경 창문과 고양이가 생긴다.
- **오답노트:** 퀴즈에서 틀린 문제가 📝 오답노트에 모인다. 다음 날 하루 사원이 복습하자고 하고, 다시 맞히면 노트에서 빠지며 +3 XP.
- **주간 복습:** 📥 받은 리포트 → 🗓 주간 복습 탭에서 그 주 데일리 퀴즈 중 최대 10문제를 푼다. 처음 풀 때 정답마다 +3 XP, 만점 +10. 금요일엔 주디 대리가 먼저 권한다.
- **업적 배지:** 연속 읽기, 퀴즈 만점, 스크랩·메모, 오답 해결 등 14가지. 받은 배지는 사무실 벽 게시판에 걸린다 (게시판이나 🏅 업적 버튼을 누르면 목록).
- **아이디어 다시 보기:** 아이디어를 쓰거나 마지막으로 본 지 7일이 지나면 하루 사원이 다시 가져온다. 생각을 덧붙이면 날짜별 기록으로 쌓이고 +3 XP (스크랩북의 💡 버튼이나 카드의 🌱 생각 덧붙이기로 언제든 열 수 있다).
- **스크랩북:** 카드의 ☆ 스크랩으로 모으고, '💡 내 아이디어' 칸에 메모한다 (처음 쓸 때 +2 XP). 📌 스크랩북에서 검색·분류하고 마크다운으로 복사해 포트폴리오나 면접 준비에 쓴다.
- **이름 바꾸기:** ⚙️ 설정에서 내 이름과 팀원 4명의 이름을 바꿀 수 있다 (비워두면 기본 이름). 직급(사원·대리…)은 그대로다.
- **클릭할 수 있는 곳:** 팀원, 내 책상(받은 리포트), 화이트보드(오늘의 키워드), 책장(스크랩북).
- 페이지를 열어두면 2분마다 새 리포트를 확인해서 팀원이 바로 보고하러 온다.
- **미리보기:** `office.html?time=09:00` (주말은 `&date=2026-10-10` 추가)처럼 열면 그 시각부터 흘러가는 것처럼 볼 수 있다 (출근 기록은 남지 않음).
- 기록(읽음·경험치·스크랩·메모)은 브라우저에 저장된다. ⚙️ 설정에서 백업 파일로 받아두고, 다른 브라우저에서 불러올 수 있다.

## 처음 설정
```bash
cd ~/claudecode/report
./scripts/schedule.sh install     # 자동 실행 등록
./scripts/schedule.sh status      # 등록 확인
```
해제는 `./scripts/schedule.sh uninstall`.

> 정해진 시각에 한 번만 실행하지 않는다. 맥이 깨어 있는 동안 5분마다 `run.py catchup`이 돌면서, 예정 시각이 지났는데 아직 없는 리포트(최근 3일 치)를 만든다. 맥이 잠들어 있었거나 꺼져 있었어도 켜고 인터넷이 연결되면 몇 분 안에 밀린 리포트가 작성된다. 같은 리포트는 하루 3번까지만 다시 시도한다.

## 📱 휴대폰에서 보기 (GitHub Pages)
리포트가 생성될 때마다 이 폴더를 GitHub에 올려서, 휴대폰에서도 `https://<아이디>.github.io/marketing-trend-office/`로 볼 수 있다.

처음 한 번만:
```bash
gh auth login                      # GitHub 로그인 (GitHub.com → HTTPS → 웹 브라우저로 로그인)
./scripts/setup_pages.sh           # 저장소 생성, Pages 켜기, 자동 업로드 설정
```
이후에는 `scripts/run.py`가 리포트를 만들 때마다 자동으로 push한다. 수동으로 올리려면 `python3 scripts/run.py publish`.

- 저장소는 **공개**다. 주소를 아는 사람은 리포트를 볼 수 있다 (리포트 내용은 공개 기사 요약). 읽음·경험치·스크랩 기록은 각자 브라우저에만 저장되므로 공개되지 않는다.
- 기록은 기기마다 따로다. 맥에서 쌓은 기록을 폰으로 옮기려면 ⚙️ 설정 → 기록 백업 받기 → 폰에서 기록 불러오기. 맥에서도 `file://` 대신 GitHub 주소로 열면 한 곳에서 관리하기 쉽다.
- 아이폰은 사파리 공유 버튼 → "홈 화면에 추가"로 앱처럼 쓸 수 있다.

## 직접 실행
```bash
python3 scripts/run.py daily
python3 scripts/run.py weekly --date 2026-10-12   # 기준일을 정해 지난 기간 리포트 만들기
python3 scripts/run.py catchup                     # 밀린 리포트를 지금 바로 확인·작성
python3 scripts/run.py render                      # 디자인만 바꿨을 때 HTML 다시 만들기
```

## 동작 방식
1. `scripts/run.py`가 기간을 계산하고 `prompts/<종류>.md`를 채워 `claude -p`(헤드리스 Claude Code)를 실행한다.
2. 에이전트는 `CLAUDE.md`의 규칙과 `sources.md`의 소스 목록을 참고해 웹을 조사하고 `data/<종류>/<기간>.json`을 저장한다.
   - 위클리는 그 주 데일리를, 먼슬리는 위클리를, 분기는 먼슬리를 먼저 읽고 웹 조사로 보완한다.
   - 데일리는 최근 7일 동안 다룬 항목을 전달받아 같은 소재를 반복하지 않는다.
3. JSON을 검증한다 (출처 URL 누락, 빈 필드 등). 문제가 있으면 한 번 더 고치게 한다.
4. `scripts/render.py`가 `reports/<종류>/<기간>.html`, `list.html`(목록), `index.html`(오피스로 이동), 오피스용 데이터 `assets/reports-data.js`를 만든다.

## 폴더 구조
```
report/
├── office.html         🏢 마케팅팀 오피스 (여기서 시작)
├── list.html           전체 리포트 목록
├── index.html          office.html로 이동 (사이트 첫 주소용)
├── reports/            생성된 HTML 리포트
├── data/               리포트 원본 JSON
├── prompts/            종류별 조사 지시문 — 내용을 바꾸고 싶으면 여기를 수정
├── sources.md          참고 소스 목록 — 자유롭게 추가·삭제
├── CLAUDE.md           에이전트 공통 규칙과 JSON 스키마
├── config.json         설정
├── assets/style.css    리포트 디자인
├── scripts/            실행·렌더링·스케줄 스크립트
└── logs/               실행 로그
```

## 설정 (`config.json`)
| 키 | 설명 |
|---|---|
| `claude_bin` | claude CLI 경로. 비워두면 자동으로 찾는다 (PATH → 에디터 확장 프로그램 폴더). |
| `model` | 사용할 모델. 비워두면 기본 모델. |
| `timeout_minutes` | 한 번 실행의 제한 시간. |
| `notify` | 완료 시 macOS 알림. |
| `open_on_complete` | 완료 시 오피스를 브라우저로 자동으로 열기. |
| `catchup_days` | 밀린 리포트를 며칠 전 것까지 챙길지 (기본 3). |

## 문제 해결
- 리포트가 안 생기면 `logs/catchup.log`를 본다. 팀원 카드에 "작성 실패"가 뜨면 그날 3번 모두 실패한 것이다.
- 자동 실행에서만 실패하고 직접 실행은 잘 된다면, 시스템 설정 → 개인정보 보호 및 보안 → 파일 및 폴더(또는 전체 디스크 접근 권한)에서 `python3`가 데스크탑 폴더에 접근할 수 있게 허용한다.
